# Worker and recovery reviews

Claude performed separate read-only S4 and S5 reviews. Raw replies are kept in
ignored local files. The first review found real worker containment defects; the
follow-up confirmed their fixes and reported no critical bug.

Accepted and implemented:

- One termination signal per child; the handler ignores further signals while
  unwinding the library's detached renderer cleanup.
- Hard fallback clock starts only when a live child receives termination. An I/O
  thread without a live child does not trigger container recycling on that clock.
- Unexpected supervisor/future failures cannot enter a blocking executor join.
- Conservative monotonic claim/lease bounds, an absolute render deadline shared
  with the child, and a remaining renderer budget capped at 300 seconds after bind.
- Brief heartbeat failures preserve the last known safe lease bound; an expired
  lease can never be renewed or used to commit a result.
- Reduced library DataLimits, atomic outcome files, safe error codes/correlation
  IDs, supervisor non-dumpable flag and an explicit child environment allowlist.
- Timeout errors classified as render failures; stale health file removed at boot;
  orphan cursor reset after storage rejection; cleanup grace floor of five seconds.

Clarifications/disagreements:

- An implicit Compose migration dependency was not added: the reviewed plan requires
  one explicit operator migration and exact revision gates on API/worker startup.
- Input/result object columns already have unique indexes from migration 0004.
  The proposed additional indexing migration is unnecessary.
- A cancelled child with an unexpected positive exit still recycles conservatively;
  an exit code alone does not prove detached-process cleanup. SIGTERM before the
  handler is installed (-15) is safely recognized separately.

Evidence at this milestone: 35 unit/integration tests passed; six container tests
passed including real Chromium-parent failure, container restart/retry with no
surviving Chromium, and a controlled barrier proving two workers with two active
slots each. Three additional real-child checks cover expired render budget,
output size and genuine dashboard overflow. Final counts are recorded separately.
