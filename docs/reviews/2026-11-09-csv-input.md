# CSV input implementation and review

Date: 2026-11-09. Baseline: 573ac5a. Target release: 0.2.0.

## Scope

Extend POST /v1/reports and the existing console with repeated CSV uploads,
an optional JSON/YAML bundle, encoding, delimiter and null tokens. Keep template
registration separate, reuse the streamed spool/object/queue path, and decode in
the isolated child. No library fork, custom CSV parser or DB migration.

The complete wire body is limited and hashed, including multipart overhead.
Normalized Content-Type stores the boundary in the existing input_type text.
Starlette/python-multipart parses the persisted input, CardReport's public
cardreport.adapters.csv.from_csv converts typed cells, and bind applies configured
limits to the combined inputs. Plain filenames are metadata, never paths.

## Claude design consultation

The read-only consultation completed with exit 0. Confirmed recommendations:

- Apply limits to the final bind, not only to individual adapters.
- Reject unknown, duplicate, malformed and incomplete multipart input; preserve
  safe terminal invalid_data outcomes instead of leaking parser/data messages.
- Canonicalize and retain the boundary, while template uploads remain JSON/YAML.
- Bound file/field counts and field bytes; close all parser resources.
- Let browser FormData construct its Content-Type and boundary.
- Document coordinated API/worker upgrades: old workers cannot parse CSV jobs.

The claim that CardReport 0.8.2 lacks a CSV adapter was rejected after reading the
installed cardreport/adapters/csv.py and the public library API documentation.
The top-level package does not re-export the adapter. Its public path-only API is
used unchanged; files are copied to generated scratch paths, not caller filenames.

A proposed closing-boundary substring check was replaced with the parser's on_end
callback, which verifies actual parse completion. On incomplete input the stream
raises inside Starlette's cleanup scope. No private parser members are accessed.
Encoding is not arbitrarily restricted to UTF-8: the public adapter supports other
Python text codecs; invalid names/bytes become DataError within existing limits.

## Implementation and focused review

Both subsequent read-only Claude consultations completed with exit 0. Neither
found a material release blocker. Confirmed improvements were implemented:

- The console accepts the literal `\t` for tab delimiters; the mixed-input browser
  test uses an actual UTF-8 BOM / tab-separated CSV with WeasyPrint.
- A container check now covers invalid CSV as well as malformed multipart.
- BOM decoding and the maximum supported option-field count have focused tests.
- Actual Swagger inspection confirmed that repeated null tokens remain separate
  fields. It also found an unselected optional file sent as an empty text `data`
  part; exactly one such placeholder is accepted as absent. Nonempty text and
  duplicates still fail. Parser field cap35 includes that placeholder.
- A real Swagger browser test uploads the reference files, examines the persisted
  multipart body, and waits for a successful report.

## Verification

checks (216 total with unit tests). It exercised both PDF engines, pure CSV and
mixed CSV/YAML inputs, terminal invalid-data errors, BOM/tab options, narrow-screen
layout, duplicate names, mode switching and Swagger's real multipart request.

against that isolated stack; both produced successful downloadable PDFs.

in the expanded CSV options. Scoped CSS makes the tokens field compact and keeps
the checkbox beside its label; existing CSV/Swagger browser tests were rerun after
that visual adjustment.
Raw review outputs and isolated test logs are retained under ignored local/.

wheel checked outside the source tree all passed. The CSV/JSON fixture comparison
normalizes the reference JSON numbers to the exact Decimal values produced by the
