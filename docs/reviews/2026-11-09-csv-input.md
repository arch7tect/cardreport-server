# Mixed file inputs and report data review

Date: 2026-11-09. Initial baseline: 573ac5a. Target release: 0.2.0.

## Final scope

POST /v1/reports accepts repeated `files` parts containing any combination of
JSON/YAML named bundles and CSV files. Dataset names must be disjoint. The console
accumulates file selections, permits individual removal, and preserves the list
on chooser cancellation. Template registration stays separate. Public CardReport
adapters remain authoritative; no library fork, inferred schema or data query engine.

Each new successful report retains a lossless snapshot of the typed inputs. The
child encodes it before rendering; the supervisor uploads unique result/data keys
and commits both through one fenced finish. Snapshots share result retention and
collection grace, independently of raw input retention. Migration 0007 adds nullable
snapshot metadata. Older results remain available without a reconstructed snapshot.

The user rejected the initial CSV-only picker plus one optional bundle before
publication. The initial 0.2 release run was cancelled before publication. That
unreleased multipart `data` alias is removed; all file inputs now use `files`.

## Claude consultations and decisions

Initial CSV design, implementation and focused reviews completed with exit 0.
They established cumulative bind limits, preserved boundary metadata, bounded
multipart resources and checked actual Swagger requests. A claim that CardReport
lacked a public CSV adapter was rejected after inspecting its installed public
`cardreport.adapters.csv.from_csv` API. The path-only API is used unchanged with
generated scratch paths. Parser completion uses its `on_end` callback rather than
a fragile substring check; unfinished parser files close inside its cleanup scope.

The revised mixed-input/snapshot design and precision-view consultations completed
with exit 0. Accepted recommendations:

- Merge files without silent overrides; add/remove a browser-owned selection list.
- Bound snapshot encoding independently of a lowered raw upload cap, using the
  public encoder's fixed 16 MiB ceiling. Fail before render on excessive expansion.
- Fence both pointers; recognize committed snapshots during orphan sweeping;
  retry partial paired deletion before marking the result deleted.
- Expose `data_available`; no snapshot for failed/older reports in this version.
- Page data views on the server; return display strings and a separate typed JSON
  download. Exact decimal digits must survive browser transport.
- Limit concurrent snapshot views, verify stored size/hash, check a monotonic
  deadline between blocking reads and recheck expiry after parsing.

Source verification refined two suggestions. Operator data limits cannot exceed
CardReport defaults, so fixed default read ceilings accept all stored snapshots.
Library names may contain slashes and dots: the page route uses an exact `name`
query parameter instead of a path segment. Library numbers are bounded to +/-1e15;
integer overflow beyond that is rejected by the engine, while precise decimals
still justify string-valued views. No custom numeric JSON parser is needed.

Rolling old/new workers is deliberately unsupported: deployment uses coordinated
pause/drain/stop/migrate/start and the existing exact schema gate. There is no
snapshot backfill or automatic downgrade after the forward-only migration.

## Verification

Meaningful checks cover mixed bundles without CSV, duplicate names, cumulative
limits, truncated bodies, BOM/tab/null options, typed snapshots and expansion
failure before render. PostgreSQL/S3 tests cover migration over existing rows,
fenced pointers, exact reads/pagination, expiry, old report availability, view
admission, referenced snapshot orphan protection and retryable paired deletion.
Browser checks cover incremental selections, cancellation/removal, both engines,
paged data views, escaped text, exact downloaded data and real Swagger uploads.

The revised implementation and focused final Claude reviews both exited 0 with
no material blockers. Confirmed fixes include explicit retry after a failed page
load, status checking before data download, checking snapshot size before either
upload, and limiting view slots to at most eight. Decimal display uses `str` to
avoid expanding a tiny exponent into unbounded fixed-point text. Global API
handlers already map storage exceptions to 503, so that suggested duplicate handler
was rejected. Source inspection confirmed bind validates without mutating inputs.
The final reviewer explicitly did not re-review the upload UI/tests in detail;
those were covered by the earlier implementation review and browser checks.

The first revised isolated run passed 43 integration, 26 container and 38 browser
tests. Final candidate acceptance is recorded below after the focused changes. Raw reviews and test evidence stay under ignored
local/; they are not published with report data or credentials.

Final local acceptance: 130 unit, 43 PostgreSQL/S3 integration, 26 container and
38 browser checks passed (237 cases). A new one-shot 503 test initially mishandled
its Playwright route; using the supported `times=1` registration fixed the test,
